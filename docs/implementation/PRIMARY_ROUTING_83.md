## Что исправлено

### Сохранение допустимых дорожных обходов

Union направлений в82 мог добавить короткое ребро, недопустимое в фактическом направлении
от источника. Неориентированный поиск выбирал его вместо существующего допустимого обхода;
последующая проверка отклоняла дерево, но уже не возвращала потерянный вариант.

В83 greedy tree проверяет направление каждого перехода, включая переходы от уже построенной
части дерева. Допуск вычисляется один раз для направленных дуг текущего графа. Виртуальный
потребитель может быть только концом пути. После сборки физическая геометрия по-прежнему
проходит независимый полный допуск.

Одного направленного greedy оказалось недостаточно для синтетического случая четырёх
потребителей. Поэтому вместе с union проверяется контрольный подграф прежних допустимых
проходов, только если он отличается. Оба строятся из текущих входных данных; это не replay
старого маршрута. Терминальные вводы вычисляются один раз и используются обоими подграфами.
Metric closure остаётся генератором кандидатов с окончательной проверкой, а не доказанно
полным направленным решателем. Влияние дополнительного подграфа на общее время ещё не измерено.

### Повторное пересечение выбранной теплосети

В82 льгота врезки исключала выбранную feature теплосети целиком. Дальнее повторное пересечение
того же объекта могло потерять special-секцию; окончательный валидатор имел ту же слепую зону.
Это затрагивает не только рисунок, но и последующие расчёты секций/стоимости.

Теперь льгота ограничена контактом у endpoint в пределах существующего координатного допуска
1 см и только разрешённым объектом типа `heat_network`. Остальная геометрия той же feature
остаётся ограничением. Совпадение ID с ОКС, водой или дорогой не отменяет их ограничения.
Одинаковое локальное правило применяется при подготовке коридора и в окончательном валидаторе.
Тест с дальним пересечением проверяет 4 м special, непрерывность секций, расход, ДУ и отказ
валидатора при удалении special с сохранённым исходным target ID.
