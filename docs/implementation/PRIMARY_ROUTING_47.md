# Основной алгоритм: геометрия и производительность

Дата: 2026-09-23. Версия: `global-tree-47`. Исходный checkpoint: `6171362` (`global-tree-46`).
Документ фиксирует реализацию и измерения, **не закрывает R4/R9 и не заявляет глобальный оптимум**.

## Один алгоритм для разработки

Новые расчёты запускаются единственной кнопкой основного алгоритма. Отдельная реализация
`ExpertExperimentalRoutingAlgorithm` удалена. Старое API-значение `expert_experimental` остаётся
совместимым псевдонимом основного алгоритма; сохранённые результаты не удаляются и не пересчитываются.
Подробнее: [совместимость](EXPERIMENTAL_ROUTING.md).

При обновлении worker сначала проверить отсутствие незавершённых задач предыдущей версии.
Не выдавать повторно запущенную старую задачу за результат её первоначального бинарника.

## Что изменено

- Поиск проверяет стоимость перехода до дорогой геометрической видимости. Недостижимые точки
  внутри запретных зон исключаются из переходов без перенумерации графа. Состояния малых графов
  хранятся в примитивных массивах; большие графы используют разреженное представление.
- Индекс ограничений сохраняет исходный порядок и дубликаты. Финальная проверка готовит
  ограничения один раз на фактический ДУ в пределах одной проверки.
- Выход из своего ОКС ищется по исходной геометрии содержащего здания, без буферизации всех
  ограничений. Финальная проверка охватывает всю полилинию, включая далёкие обходы.
- Проверяются все свободные камеры-кандидаты. Непригодный ближайший/самый дешёвый кандидат
  больше не скрывает следующий допустимый. Дополнительный короткий подход позволяет использовать
  четвёртый луч камеры с правильным направлением вместо безусловного создания ещё одной камеры.
- Два допустимых новых луча могут использовать одну существующую камеру. Совпадающие врезки
  в одну точку участка имеют общий физический узел; разные точки одного участка остаются разными.
- В портфель добавлены общие групповые магистрали: осевые коридоры по геометрии застройки
  и деревья от общей врезки с дальнейшим присоединением потребителей. Проверяются расходы,
  фактические ДУ, степень узлов, препятствия и стоимость всей сети. Координаты/ID примера не зашиты.
- Реальные контуры и порталы вогнутых дворов используются как fallback **после** обычных
  коридоров 75/200/600 м. Они не подменяют уже найденный допустимый обычный путь для того же запроса.
- После последнего изменения геометрии повторяется sizing; после него геометрия больше не
  меняется. Ошибки sizing исключают вариант из допустимых. При повышении до предыдущего ДУ
  непрерывная длина суммируется, а не обнуляется.

Готовые результаты между расчётами не кешируются. Измерения получены новыми вычислениями;
подготовленные геометрические структуры и существующая мемоизация подзадач живут только внутри
одного расчёта. Поисковые ограничения остаются эвристическими, обещание «идеального алгоритма»
не является доказанным свойством.

## Что показывает интерфейс

Первым открывается допустимый инженерный вариант с максимальной полнотой подключения.
Серверные `preferred_variant_id`, rank и целевой показатель не меняются; другие варианты доступны
во вкладках. Ручной выбор не сбрасывается обычным обновлением данных.
Названия «Приоритет длины» и «Приоритет стоимости» обозначают цель эвристики, а не доказанный
глобальный минимум: окончательная регуляризация может изменить взаимный порядок длин.

Отдельно считаются камеры ветвления, новые камеры врезки, физические места подключения и новые
лучи. Одна существующая камера с двумя лучами — одно место, но две оплачиваемые врезки.
Полученные от backend инженерные предупреждения отображаются. Для варианта стоимости backend
исторически не публикует `engineering_issues`; интерфейс явно предупреждает, что у него возможны
нерегулярные углы. Пустой список в этом варианте нельзя трактовать как отсутствие таких углов.

Источник: неизменённый `datasets/official/lct-2026.geojson`, SHA-256
`cffb7133419d93fe364a53015a7d3ead289f671cbfaf6f4befe87f2a21914130`, 17 потребителей.
Java 11; свежий JVM на каждый тест. Время ниже — JUnit suite, не время сборки Maven.
Замеры на общей рабочей машине, не изолированный нагрузочный benchmark.

| Прогон | Время | Что доказано |
|---|---:|---|
| Исходный `6171362` | 930,556 с | 3 допустимых варианта, 17/17, depth=true |
| Только первые безопасные ускорения | 306,964 с | Весь результат точно совпал с исходным, кроме версии |
| Промежуточный расширенный поиск | 509,813 с | Общая сеть с 1 местом/2 лучами, но выросли цена и длина |

Во втором промежуточном варианте balanced/shortest совпали; balanced имел 15 новых камер,

### Итоговая проверка global-tree-47

Полный 17-ОКС testcase: **451,725 с** против **930,455 с** у исходного checkpoint — наблюдаемое
ускорение **2,06×**. Весь класс с дополнительными проверками пяти одиночных ОКС: 463,972 с.
В финальном запуске одиночные ОКС предшествовали полному тесту, JVM был прогрет; одновременно
проверялся живой API. Это не контролируемый изолированный benchmark.

| Вариант | Длина, м (изменение) | Стоимость, ₽ (изменение) | Новые камеры, было → стало | Нестандартные углы, было → стало |
|---|---:|---:|---:|---:|
| engineering / balanced | 1 899,051 (+5,48%) | 269 806 210,70 (−0,56%) | 15 → 12 | 3 → 0 |
| shortest | 1 904,773 (+6,14%) | 266 452 933,01 (−3,27%) | 16 → 11 | 3 → 0 |
| cheapest | 1 904,725 (+8,06%) | 266 087 216,11 (−0,34%) | 15 → 11 | 17 → 14 |

Все три геометрии различаются; у всех 17/17 подключений, одно дерево без циклов, одно физическое
место и один новый луч вместо четырёх мест/лучей. Новых камер врезки нет. Ошибок финальной
геометрии/sizing — 0, степень камер ≤4, баланс расходов проверен. При включённой глубине
85/85 профилей завершены без ошибок; metadata правильно содержит `depth_enabled=true`.

**Ограничение:** конкурсный показатель относительно старого одноимённого варианта вырос
на 1,95% / 0,60% / 3,14%. Снижение стоимости не компенсировало увеличение длины.
Два инженерных варианта теперь проходят проверку углов/колен, но это не Pareto-улучшение по
всем метрикам. Дальше нужно сохранять сильные короткие альтернативы при построении общей сети,
не ослабляя ограничения; gate «без ухудшения целевого показателя» не закрыт.
Осевые групповые коридоры проверены на синтетических случаях; на официальном файле 12 таких
предложений отклонены валидаторами. Приняты криволинейные деревья от общей врезки.

## Как повторять перед слиянием

1. Java 11 `mvn verify`; включать оба теста `OfficialDatasetRoutingTest`, а не только unit suite.
2. `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm build` на поддерживаемом Node (локально 24.19).
3. `node scripts/reference-routing-benchmark.mjs`.
4. Новая задача через настоящий API/PostGIS: импорт → расчёт → карта → официальный экспорт.
5. Сравнить 17/17, допустимость, расходы/ДУ/предельные длины, стоимость, длину, новые камеры,
   места/лучи, углы/короткие колена, различимость вариантов и время. Хранить полные артефакты
   локально в игнорируемой `.tooling`; в Git — методику и сводные результаты.
6. Отдельный обязательный Compose smoke в окружении с Docker. На этой macOS-машине Docker/pwsh
   отсутствуют: нативный smoke не считается выполнением Compose gate.

Изменение поискового бюджета, правил или поколения кандидатов требует нового полного прогона.
Отсутствие геометрических ошибок не равно отсутствию инженерных замечаний.
