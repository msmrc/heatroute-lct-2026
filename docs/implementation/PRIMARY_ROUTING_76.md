## Проверенная, но не принятая численная подготовка

- Эвристика вычисляется один раз для каждого узла текущего поиска: дополнительный `double[N]`.
  Используется исходная цель, как раньше, даже если heading округляет узлы до миллиметров.
- Входящий вектор и его `Math.hypot` вычисляются один раз на раскрываемое состояние,
  а не заново для каждого исходящего перехода. Штраф поворота сохраняет порядок операций,
  исходные координаты и все пороги. Миллиметровый предикат разрешённого угла не меняется.
- Очередь, visibility, порядок релаксаций, epsilon/tie-breaking и проверка геометрии не меняются.
  Нет кэша готовых маршрутов, повторного использования результатов между запусками или
  лимита качества поиска. Подготовка жила только внутри одного вызова.

Независимая проверка:6962exact-comparisons без расхождений, одинаковые190114visibility checks,
80192bitwise-equal bend results; оба epsilon-контрпримера ниже проходили. Но ограниченный
замер на реальном park-графе231узел/8649visibility checks не показал ускорения:
median CPU6,341→6,484мс(+2,3%), allocation+1864байта/search. Это24прогревов/версию и20чередующихся
серий×3поиска; не замер всей системы и не доказанная устойчивая регрессия. Финальное размещение
сложения priority отдельно не измерялось. Без подтверждённого выигрыша patch тоже удалён.

## Отклонённая гипотеза: верхняя граница по приоритету цели

Первый вариант отсекал переходы с приоритетом выше уже допущенной цели +`max(1e-9,8ulp)`.
Он прошёл обычные тесты, 6962 seeded/real differential cases и предварительный быстрый Maven,
но **два направленных reviewer-контрпримера изменили выбранный маршрут**.

Причина: несколько последовательных обновлений предшественника могут каждое укладываться
в `1e-9`, но вместе перейти границу. Даже ещё не раскрытое состояние выше приоритета цели
влияет на сравнение следующих кандидатов. Отсечение только впервые открываемых состояний
тоже не сохраняет результат. Увеличивать допуск без доказательства не стали.

Отсечение полностью удалено. Его 32% экономии проверок на синтетическом графе и предварительные
1135cases/1132PASS/3skip **не являются gate конечного checkpoint**. Два контрпримера сохранены в
`OfficialObstacleRouterSearchPriorityTest`: RED на отклонённом варианте, GREEN на production75.
Этот checkpoint не исправляет саму историческую семантику epsilon; такое изменение должно
быть отдельным correctness-патчем, а не скрытой частью ускорения.
