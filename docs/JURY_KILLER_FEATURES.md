# HeatRoute: киллер-фичи для жюри

## Версия на 20 секунд

HeatRoute не прокладывает 17 независимых линий. Он за один запуск синтезирует **единую физическую
тепловую сеть** для всех объектов: выбирает присоединения, находит общие стволы, суммирует расходы,
назначает ДУ, проверяет ограничения и считает стоимость. На конкурсном наборе HeatRoute
подключил 17 из 17 объектов за 15,918 секунды без ошибок геометрии, engineering и sizing.

## Семь тезисов, которые стоит произнести

1. **Оптимизируем сеть, а не набор маршрутов.** Общий ствол выбирается одновременно для нескольких
   ОКС, строится один раз и оплачивается один раз.
2. **Геометрия и математика разделены.** Геометрический слой создаёт только физически допустимые
   трассы, а CP-SAT собирает из них совместимую связную топологию в пределах каталога.
3. **Нет двойного учёта общей инфраструктуры.** `PhysicalAssetCompiler` объединяет совпадающие
   участки до оптимизации, поэтому модель считает реальную трубу, а не наложенные линии.
4. **Решение проверяется после оптимизации.** `FrozenNetworkEvaluator` заново собирает сеть,
   считает потоки и ДУ, проверяет камеры, пересечения, длины и стоимость.
5. **Алгоритм умеет исправлять собственные конфликты.** При точечной проблеме он расширяет только
   нужную часть каталога и повторяет синтез, а не пересчитывает всё пространство вслепую.
6. **Один расчётный контур.** Production API запускает HeatRoute или возвращает диагностику.
   Версия алгоритма записана в каждом run и видна через Swagger.
7. **Результат готов к интеграции.** На выходе строгий GeoJSON, OpenAPI и JSON Schema; запуск
   воспроизводится по SHA-256 входа, версии алгоритма и сохранённым параметрам.

## Главный технический козырь

> Мы превратили непрерывную городскую задачу в проверяемый цикл
> «каталог физических трасс → CP-SAT-топология → точный инженерный допуск».
> Поэтому HeatRoute ищет общую сеть быстро, но не публикует математически красивый вариант,
> который нельзя построить.

## Проверяемая цифра

Повторный контрольный VPS-run от 29.09.2026: сборка алгоритма 6, 17/17 подключений, один валидный
вариант, 2 170,113 м новой сети, 300 092 048,85 ₽, 0 ошибок validation, engineering и sizing,
15,918 с между созданием и завершением run. Cold run занял 19,017 с.

Формулировка для слайда:

> **17 объектов → единая проверенная сеть за 15,918 с**
>
> Не 17 кратчайших линий, а совместная топология с общими стволами, расходами, ДУ и стоимостью.

## Что не следует обещать

- не называть найденный вариант доказанным глобальным оптимумом на непрерывной плоскости;
- не переносить 15,918 с на любой скрытый набор без оговорки о сложности геометрии;
- не утверждать, что три варианта обязательны: система возвращает до трёх, если они действительно
  различаются;
- не говорить, что `score` заменяет критерии конкурса: он ранжирует варианты внутри одного
  решения;
- не выдавать optional depth за обязательное условие 2D-результата.

Честная формулировка сильнее: это bounded-оптимизация с точным финальным допуском и
воспроизводимым production-run.
