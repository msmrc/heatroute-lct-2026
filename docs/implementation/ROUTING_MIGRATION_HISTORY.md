# История перехода к единому алгоритму HeatRoute

До 2026-09-29 команда проверяла отдельные исследовательские конфигурации маршрутизации. Этот
контур полностью удалён из production-кода, API и интерфейса: новый расчёт всегда выполняет
`HeatRouteRoutingAlgorithm`, который вызывает `HeatRoutePlanner`.

Сохранённые результаты прежних запусков остаются неизменяемыми и открываются без автоматического
пересчёта. Новые запросы не принимают выбор алгоритма и не содержат скрытого запасного пути.
Версия вычислительного ядра записывается в результат, поэтому воспроизводимость сохраняется без
параллельных продуктовых веток.

Историческая реализация используется только как тестовая регрессионная фикстура и не попадает в
production JAR. Она нужна, чтобы проверять геометрию, ограничения и экспорт при дальнейшем развитии
ядра. Актуальные правила работы описаны в [ALGORITHM.md](../ALGORITHM.md), состояние проверок — в
[roadmap](OFFICIAL_TZ_ROADMAP.md) и [progress](progress.md).
