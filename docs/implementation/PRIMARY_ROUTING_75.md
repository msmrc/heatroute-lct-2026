## Воспроизведение

`ensureMandatoryEgress` отрезал последнее звено и проверял две части как законченные road/tram
пересечения. Техническая коллинеарная вершина внутри crossing давала обеим частям
`SPECIAL_CROSSING_EXTENSION_MISSING`, хотя целое ребро проходило независимый валидатор.
После этого восстановительный поиск менял нормаль на другую ближайшую стену.

Реальные RED до исправления:2FAIL/4controlPASS, road и tram. Исходное допустимое ребро81м
с одним8м special превращалось в другой допустимый путь30,087м без crossing. Это доказывает
потерю сохранения эквивалентной геометрии из-за одной технической точки, **не** ухудшение
стоимости/связности официального датасета. При удалении только этой коллинеарной вершины
старый алгоритм сохранял81м. При удалении дороги сохранение также работало.

## Исправление

- Новый `terminalRouteAllowed` получает полную исходную полилинию root→demand. Наружная часть
  проверяется со всеми своими отступами, последнее звено — только с разрешённой локальной
  льготой собственного ОКС/содержащей социальной территории. Чужие запреты и принятые трассы
  остаются препятствиями. Существующие явные проверки запрещённых конечных точек сохранены.
- Незаконченные части проверяются как звенья, но road/tram допускается **одним** полным guard
  всей трассы: реальные защитные длины, прямолинейность, входной угол и параллельный отступ.
  Геометрия не разворачивается: угол реального входа зависит от направления.
- Пространственное окно покрывает всю полилинию. Endpoint-льготы определяются настоящими
  концами ребра, не технической точкой разделения. Добавлен отрицательный тест старого
  ошибочного допуска чужого отступа через эту искусственную endpoint-льготу.
- `hasMandatoryEgress` остаётся перед новым guard; ветка без ввода использует прежний
  `lineAllowed`. Реальные нарушения по-прежнему идут в восстановительный поиск.
  При успехе возвращается тот же `RouteEdge`: координаты, секции, ДУ, расход и metadata
  не заменяются повторно построенной/округлённой геометрией. Двухточечный ввод также поддержан.
- Это исправление границы **внутри одного логического ребра**. Переходы через несколько
  логических рёбер и кандидаты нормалей с асимметричной дорогой внутри самого ввода — отдельный scope.
