# Доводка65: короткие переходы от наклонной нормали к коридору

Дата:25.09.2026. База `3abac08`, ветка `codex/routing-63-geometry`.
Единственный основной алгоритм `global-tree-65`; локальный API пока остаётся на JAR61.
Это промежуточный этап доводки, не утверждение готовности к сдаче или оптимальности сети.
Код `aff1dcf` отправлен в origin, remote SHA проверен. Full-quality gate не закрыт.

## Изменение

`NormalCorridorTransitions` предлагает диагональное среднее звено в подходе с двумя
поворотами. Оно соединяет наклонную нормаль реальной стены с осевым приходом в порт.
Прежние варианты сохранены; для совпадающих осей ввод остаётся прямоугольным.
Добавлены только аналитические пересечения лучей с прежними пятью смещениями: не более
84 предложений вместо44, без глобального перебора или кеша готовых маршрутов.
Сохранение прежних геометрий в генераторе не доказывает сохранение всего портфеля:
ограниченный отбор вводов/портов может измениться; это проверяется отдельным fresh-прогоном.

Первый внутренний угол ограничен90–135°, второй равен135°. Полный обязательный ввод,
отступы, минимум2м между поворотами, ось конечного участка и проверка после миллиметрового
округления не ослаблены. Это расширение генератора кандидатов, не новое инженерное правило.
Координаты/ID официального набора не используются в production-коде.

## Следующий проверяемый дефект

Read-only контрпример выявил разные нормали при построении anchors и spurs:
`OrthogonalCorridorNetworkBuilder` берёт для anchors ДУ суммарного расхода, для spurs —
индивидуальный. Базовая ориентация от ДУ не зависит, дополнительная terminal-frame — зависит.

Синтетический ОКС `[0,20]×[0,20]`, потребитель `(2,8)` с расходом1→ДУ50, парк
`[-10.5,-9.5]×[5,11]`; второй потребитель `(60,40)` с расходом1000, суммарныйДУ500,
корень `(-25,40)`, ориентация0. Западный вводДУ50 `(-5.45,8)` допустим, но общийДУ500
выбирает южный `(2,-8.085)`. Общие anchors не предлагают порт `(-5.45,28.335)`.
Добавление индивидуального anchor при неизменных проверках **ствола поДУ500** сокращает
контроль «сетка от корня + локальный ввод»79,00→63,04м; обе линии прошли геометрическую и
инженерную проверки в JShell. Это локальное свидетельство, не новый whole-dataset результат.

Следующий этап: превратить пример в RED regression, сохранить общие anchors и добавить
индивидуальные, не подменяя ширину/проверки ствола меньшимДУ. Затем rotation/translation/
permutation и свежие17/17/export/score/cameras gates. Отдельно исследовать сохранение старых
портфельных контролей: по одним опубликованным трём ролям нельзя установить, где исчезла
прежняя сеть1983,620м. Не менять objective из-за одного неудачного сравнения.

Другие гипотезы, **не доказанные исправления**: полезные переносы камеры дальше40м могут
быть недоступны локальному поиску; одинаковая геометрия с разными strategy-метками может
повторно проходить refinement. Перед изменением нужны отдельные контрпримеры/эквивалентность,
а не увеличение радиуса или удаление полей identity вслепую.
