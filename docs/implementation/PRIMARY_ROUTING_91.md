# Source91 — сборка секций без повторной подготовки запрещённых буферов

Тип изменения: локальная оптимизация с сохранением поведения. Версия `global-tree-91`.
Не меняет поиск деревьев, диаметры, правила отступов, отбор ролей и формулы стоимости.
Не добавляет кеш маршрутов. Runtime61/VPS не обновляются этим checkpoint.

## Причина и изменение

В 40-секундном JFR-фрагменте fresh90 этапа общих коридоров получено2393 CPU samples.
У1846 ближайший прикладной frame — `OfficialRouteGeometryRules.baseConstraints:91`;
1794стека включают `OrthogonalCorridorNetworkBuilder.compress:579`. Значительная часть
сборки повторно строит запрещённые буферы для очередного ДУ ребра, хотя
`completeCheckedAssembly` использует только целые road/tram-пересечения и разметку секций.
Это профиль одного фрагмента, не доля времени всего расчёта и не SLA benchmark.

`completeCheckedCorridorAssembly` получает из того же полного пространственного окна
только незапрещённые ограничения. Подготовка секций сохраняет фактический ДУ, все типы
пересечений, порядок ограничений и локальный контакт с выбранной теплосетью. Для нестандартных
правил/каталога/геометрии используется прежний путь подготовки. Новый частичный набор
не выдаётся вызывающему коду как пригодный для проверки свободного прохода.

Проверки каждого звена ствола на общем ДУ, вводов на их ДУ, независимая итоговая проверка
после sizing, глубина и сохранённый экспорт90 не меняются. Важная граница:
`completeCheckedAssembly` **и раньше не проверял запрещённые отступы повторно**. Он не может
заменить проверки звеньев или оправдать сетку с меньшим ДУ. Обновлён устаревший JavaDoc
`PreparedCorridor`: у корня нет общего исключения отступа ОКС.
