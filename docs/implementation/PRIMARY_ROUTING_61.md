## Причина и реализация

1. Одна средняя ось фасадов68,909° не совпадала с плотным семейством допустимых вводов
   около68,037°. Эти значения **измерены**, не зашиты в код. Новый
   `CorridorTerminalOrientation` выбирает одну наблюдаемую ось, с ограниченными входами
   ≤64 терминалов/≤64 направлений на терминал, периодом90° и детерминированным отбором.
   Пороги6°/0,25°/0,1° — поисковая эвристика, не нормативы. Повторы одной семьи не увеличивают
   её вес. Контрольная сетка остаётся; альтернативная добавляется только для первого
   геометрически выбранного корня группы, а не для каждого кандидата врезки.
2. Выбранная ось передаётся одновременно сетке и маршрутизатору вводов. Ранее grid
   вычислял её снова по anchors; возможное расхождение fallback не объявляется доказанной
   причиной на официальном входе, но явная передача исключает такое рассогласование.
3. `CorridorPortCompatibility` после прежних проверок пересечений проверяет внутренние
   повороты ввода и стык степени2 тем же `OfficialRouteDeflectionRules`. Негодный порт
   возвращается существующему ограниченному поиску альтернатив. Степени3/4 не получают
   выдуманный запрет на угол между ветвями. Лимит8 попыток `CorridorPortSearch` не изменён.
4. Удаление почти прямых вершин могло сделать допустимую полилинию недопустимой: допуск
   миллиметрового округления уменьшается при удлинении хорды. Реальный пример после
   сжатия давал90,015468°. Теперь проверяется сжатая линия; при неудаче сохраняются
   исходные точки. Никакие дополнительные вершины или угловые допуски не добавляются.
   Это сохранение исходного принятого пути, не доказательство геодезической точности.
5. Уже регуляризованные коридорные победители также участвуют в существующем bounded
   объединении камер. Иначе проходил только их исходный portfolio draft с ещё неудобным
   вводом. Ширина/число уровней refinement и финальный selector не ослаблены.

## Исследование до интеграции

Изолированный builder заново строил сети из входной геометрии; reference и сохранённые
маршруты не использовались как seed. Сохранённый58 result использовался только для
проверки input SHA и метаданных export. Оси: baseline68,909105756°, median68,098771267°,
mode68,037454462°; сравнивались baseline и mode у ближайшего к центру группы корня.

- Baseline:23 собранные сети,12 raw-уникальных допустимых; mode:21, ни одной raw-допустимой.
- После ранней проверки стыков mode даёт2 raw-уникальных допустимых; после защиты сжатия11.
  В14 вызовах сжатия воспроизведён переход «углы до PASS, после FAIL»; это не14 разных сетей.
- Штатная regularization/refinement двух свежих mode-draft:3 принятых законченных seed,
  10 принятых refined-вариантов,35,004 с. Среди них1880,923 м/12 камер/16 поворотов/
  272831774,73 ₽;11-камерные варианты имеют20–22 поворота. Не все они выбираются selector.
- Полный61 plan выше, а не этот изолированный probe, подтверждает динамический результат.

Независимый read-only разбор также воспроизвёл неполноту жадного дерева на абстрактном
взвешенном графе:8 узлов/10 рёбер, корень с2 местами, три листа с3 резервами каждый.
Индивидуальные короткие пути занимают корень; greedy с любым первым листом и metric closure
возвращают null, хотя общий ствол с весом11 проходит на своём подграфе. Это **не** доказанная
причина результата официального набора. Следующий алгоритмический резерв — ограниченные
совместные пары/тройки потребителей при начальном построении дерева, а не новые локальные
переносы. В61 это не реализовано.

Основной агент независимо повторил абстрактную пробу на target61:1024 подмножества рёбер,
7 допустимых деревьев, минимум веса11; все10 greedy/seeded/metric запусков вернули null,
на подграфе оптимального ствола штатный builder успешен. Граф: root0→shared1 вес8;
дляi=0..2 root0→private(2+i) вес6, private→leaf(5+i) вес1, shared1→leaf вес1.
Root capacity2, каждый leaf резервирует3. Координаты(i·0,1;0) — только API графа, это **не**
геометрически допустимая трасса. Probe `.tooling/Global61TreeCompletenessProbe.java`.
Следующий gate: bounded совместное подключение пары/тройки через общий узел; сначала
независимый oracle/focused test, затем ограниченные fresh official-кандидаты, полный допуск
и сравнение времени. Reference не использовать как seed.
