# Source89 — точный подход к неподвижной камере

Тип: исправление пробелов поиска геометрии и изменение ограниченного бюджета локальной доводки.
Не отдельный алгоритм, не копирование ручной схемы, не ускорение за счёт кеша.
Правила источников и неизменный официальный контракт — в [source88](PRIMARY_ROUTING_88.md).

## Что изменено

- К четырём возможным переносам добавлена исходная позиция камеры. Выправление подхода теперь
  возможно, когда перенос не нужен или в радиусе поиска нет подходящих опорных точек.
- Только для этого этапа включается `buildForChamberQuality`: до двух мест среза хвоста,
  до 38 новых хвостов плюс перепроверенный исходный путь, до восьми итоговых альтернатив.
  При неподвижном конце префикс не проходит через старую камеру, чтобы не создавать петлю.
  Нормальный ввод ОКС, направление потока, препятствия и сохранённые рёбра проверяются прежними
  средствами. Обычный `build` сохраняет прежний набор вариантов.
- `choosePrecise` ищет совместимые лучи 90°/180° с допуском evaluator 0,5°. Обычный локальный
  `choose` остаётся с прежним поисковым допуском 5°. Это режим генерации кандидата, не новая
  обязательная норма; пересечения, официальный угол двухзвенного стыка и отмена не отключаются.
- Ось этой доводки определяется магистральными связями, исключая вводы потребителей. Ранее
  длинный косой ввод мог перевесить технически раздробленную прямую магистраль: исправление
  одной камеры тогда портило лучи соседних. Общая ориентация остальных стратегий не меняется.
- При одинаковом числе нерегулярных пар сравниваются отклонения **сверх** допуска округления,
  затем экономика. Не платим за точные 90° вместо уже допустимых 89,999°. Сами per-node и
  агрегатные проверки сохранения качества не ослаблены.
- Локальный поиск ограничен **тремя** проходами вместо двух: три разные проблемные камеры
  не требуют второго запуска с новым бюджетом. До двух финализаций за проход, до шести
  принятых соседей на seed, до двенадцати на две роли. Цена/длина остаются в пределах 105%
  одного исходного seed и исходного balanced; накопления запаса между проходами нет.

## Обнаруженный открытый дефект допуска — следующий correctness scope

Подтверждён B-10: `OfficialRouteGeometryRules.applicableConstraints` заменяет буфер ОКС контуром,
если конец участка находится внутри отступа вне здания, не различая новую камеру и существующую
врезку. На синтетическом building в6,5м от **новой** камеры independent validator88 пропускает
нарушение фактического отступа для ДУ500/600. RED: 2 failures / 3 controls PASS; сохранён отдельно
`.tooling/chamber-safety.jBjWz5/endpoint-reproducer/OfficialChamberQualitySafetyTest.java`.
Это ещё не свидетельство выбора такого дефекта самим новым repair, но независимый допуск неполон.
В зелёном safety-наборе дополнительно проверяется interior-отступ всей полилинии, а RED не скрыт.
Следующий шаг — отдельный focused regression и ограничение исключения действительным локальным
подходом существующей врезки, без снятия нормального ввода ОКС и без ослабления отступов.

Открыты: B-10, свежий89, дороги17/17, compact, геометрия всех ролей (cheapest ещё может сохранять
плохие лучи), время полного расчёта, экспертный профиль 2/3м и176–180°, native/Compose/scale.
Официальный rank/preferred не менялся; UI может по-прежнему первоначально показывать cheapest,
поскольку метрика лучей ещё не включена в `engineering_issues`. Наличие чистого balanced не
означает, что все роли или вариант по умолчанию уже имеют эту геометрию. Нужен отдельный
согласованный инженерный допуск/предупреждение без подмены конкурсного score.
`pwsh`/Docker отсутствуют на этом Mac; их gates не заменяются Maven/web. R/G и общая цель не закрыты.
