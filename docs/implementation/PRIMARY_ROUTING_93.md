# Source93 — нормали камер с приоритетом ТЗ ЛЦТ

## Требование и источник

Работа только в master. Основание: [активные источники](ACTIVE_ROUTING_RULES.md).
Свежий Google-документ получен 25.09.2026; SHA-256
`bcf063eee20d881a6a5a29b3bef68b4ddb5931558d603575f9345133c28bb760`,
снимок `.tooling/expert93/rules-google-latest.txt`. Добавлены явный запрет примыканий
45/135° и пояснение «минимум 2 м»; строка про 100° дороги удалена.

Последнее прямое решение пользователя: Google применяется **если ТЗ ЛЦТ не указало иное**.
Техническое приложение §2.1 (стр. 1) разрешает изменение направления 0–90°,
а §4 табл. 2 (стр. 4) задаёт дорогу с углом не менее 45°. Эти требования имеют приоритет.
Ужесточение дороги до 90/90–100° отменено, код и тесты дорожного правила восстановлены.
Угол трубы 135–180° допустим; обычный поворот нельзя отклонять по диапазону Google90–135°.

Камеры: примыкания по нормали, ветви перпендикулярны магистрали, прямое продолжение допустимо.
Ближайший фактический поворот не менее чем в 2 м от камеры; технические/коллинеарные вершины
не сбрасывают расстояние. Короткий прямой ввод камера→ОКС без поворота допустим.
Максимум четыре примыкания, минимум 10 м по трассе между камерами и минимум 2 м между
соседними поворотами сохраняются. Дополнительных правил из СП нет.

## Реализовано

- Независимая проверка направлений 90/180°, ближайшего поворота и непрерывной геометрии
  через технические узлы. Существующая сеть задаёт занятые направления и вместимость камеры.
- Нормальные подходы в генераторе, обязательный ремонт перед назначением ролей,
  сохранение направлений камеры при обходе препятствий по глубине.
- Независимый контроль допустимых по ТЗ поворотов и расстояния 2 м, включая сохранённый
  JSON и округлённую геометрию экспорта. При отказе preflight поток выдаёт 0 байт.
- Изменение инженерной оценки: внутренние углы 90–180°; дополнительного запрета
  на разрешённые ТЗ плавные повороты нет.
- Перестройка соседних камер допускает только улучшение промежуточного кандидата;
  окончательный допуск остаётся строгим. Ограниченный поиск свободного луча восстанавливает
  подход к ОКС, когда локальных L/Z-вариантов недостаточно.
- Направление и прямой участок камеры сохраняются при росте ДУ и обязательном обходе
  собственного ОКС. Отдельный регрессионный тест воспроизводит DU125→150 в трёх поворотах.
- Неисправимые исходные камеры отбрасываются до ограничения числа ближайших врезок:
  несовместимые существующие направления не вытесняют более далёкую допустимую камеру.
  Тесты используют переносы, повороты и замену идентификаторов; специальных ID в коде нет.

## Следующие найденные несоответствия

Полная цель остаётся активной. При завершении release93 аудит выявил:

- shortest/cheapest локального результата одинаковы, а на VPS одинаковы все три роли.
  §6 приложения требует до трёх содержательно различных вариантов; разные названия ролей
  сами по себе не подтверждают разнообразие.
- own-OKS normal egress пока снимает также ограничение содержащей `social_area`.
  Письменное исключение §2.2 относится только к своему `oks`; остальные ограничения сохраняются.
  Этот исторический допуск подлежит отдельному исправлению, дороги/детсад17/17 не приняты.
- После обязательного ремонта камер пропущен повторный bounded этап объединения камер.
  Проверенный replay даёт2025,854м/13узловых+1врезка/285083697,19₽,17/17 и strict export PASS.
  Это доказательство возможности улучшения, ещё не свежий результат runtime93.
