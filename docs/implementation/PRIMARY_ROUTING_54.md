# Primary routing 54 — удаление допустимых лишних ступенек

**Дата:** 24.09.2026. **Статус:** финальные локальные fast, dataset/export и web gates PASS.
База — [source53](PRIMARY_ROUTING_53.md). На официальном наборе выбранные сети не изменились.
Live API остаётся49; новый runtime/Compose не проверен. Цель по геометрии/скорости не закрыта.

## Причина и границы изменения

`regularizeFinishedEngineeringEdges` посещал только `nonCompliantEdgeIds`. Поэтому уже
допустимая полилиния с лишним обходом не упрощалась. Минимальный настоящий `finish` fixture
с нормальным вводом в свой ОКС сохранял141 м и4 поворота при доступном допустимом пути81 м
без поворотов. Красный regression на53: `.tooling/primary54-simplification-red.log`.
Это оптимизация геометрии по текущим требованиям, не новое правило из СП.

`RetainedEndpointSimplifier` предлагает сокращение только внутренней внешней части ребра:

- первые и последние звенья остаются неизменными; камеры и их лучи не перемещаются;
- внутри буфера своего ОКС сохраняется весь исходный подход, а не снимается ограничение;
- у неизменённых префикса/суффикса сохраняются секции; у нового участка пересчитываются;
- используется существующий локальный `regularize`, без нового глобального поиска;
- рассматривается не более512 вершин одного ребра, один проход по готовому варианту;
- межзапускового сохранения готовых маршрутов для переиспользования нет.

При пустом исходном списке секций оптимизация не применяется. Это допустимый старый fallback
модели, но `splitAt` не может сохранить отсутствующие секции: regression показал81 м геометрии
при20 м секций и недосчёт4 515 403 ₽. Исходный fallback экономики считает всю линию корректно.
Защита проверяется до копирования координат; ограничение512 вершин также предшествует копированию.
Красный лог: `.tooling/primary54-retained-empty-sections-red.log`.

Сам helper возвращает кандидата, а не подтверждённый маршрут. `finish` сохраняет исходный
проверенный вариант и принимает замену лишь при меньшем числе поворотов без ухудшения
остальных инженерных показателей и без удорожания. До повторного finish каждый shortcut
проверяется в составе всей сети. Затем повторяются sizing, обязательный ввод, глубина,
финальная геометрия и экономика. Только валидный, полностью оценённый и более короткий
результат с меньшим числом поворотов и неизменными концевыми звеньями заменяет исходный.
При включённой глубине нужны полные профили без ошибок. Топология и подключения не меняются.

Сокращение камер — отдельная следующая задача: эта эвристика удаляет лишние изломы, а не
заменяет обязательные камеры ветвления точками LineString. Правила и границы применимости
СП описаны в [справке](ROUTING_STANDARDS_APPLICABILITY.md).

## Следующий геометрический шаг, не выполнен в54

Проверить именно перестройку ветвлений, а не ещё одно увеличение числа точек полилинии.
У preferred13-камерной сети найдены четыре смежные пары тройников в текущем радиусе80 м:
длины связей43,727 /53,074 /55,303 /75,288 м. Следовательно, лимит четырёх пар сам по себе
не объясняет отсутствие дальнейшего улучшения именно этого состояния. У других seeds
пар может быть больше; вывод не распространяется на весь поиск.

Нужен ограниченный диагностический прогон от актуальных победителей с фиксацией причины
отклонения: несовместимые направления, препятствия, независимый finish, score или ограничение
фронта. Только после этого выбирать перенос камеры, обмен соседними ответвлениями или другой
набор начальных сетей. Сейчас refinement раскрывает максимум два состояния на каждом из трёх
уровней и принимает только уменьшение числа камер; перестройки с тем же числом камер он
не генерирует. Это ограничение эвристики, не доказательство невозможности более хорошей сети.
Координаты/ID Евгения не должны попадать в генератор; они остаются только сравнительным входом.
