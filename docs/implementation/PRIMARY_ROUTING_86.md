# Основной алгоритм86 — правила камер на экспорте и сохранение углов при укорачивании

25.09.2026. Два correctness fix после [85](PRIMARY_ROUTING_85.md), не рефакторинг,
не новая норма СП и не полная приёмка результата. Версия исходников `global-tree-86`.

## Независимая проверка сохранённого результата

`SavedChamberAssessment` применяет `ExpertChamberRouteValidator` до выдачи первой feature:
ввод начинается в камере, между последовательными камерами минимум 10 м **по трубе**.
Технические точки не сбрасывают расстояние; короткий ввод камера → ОКС остаётся допустимым.
Проверяются все пять входов exporter, включая выбранный вариант и потоковую выдачу.

Фактическую метрическую длину считает уже существующий однопроходный геометрический
preflight, без копии полилинии и дополнительного обхода координат. Заявленное `length_m`,
сохранённый `valid=true` и номер алгоритма не заменяют проверку. Новое правило применяется
также к старым и неверсионированным расчётам. Неверный результат требует перерасчёта через
существующий `OFFICIAL_EXPORT_INCOMPLETE`; чтение JSON и сами сохранённые данные не меняются.

24 новых случая: 17 RED + 7 контрольных PASS до исправления → 24 GREEN. Включены
9,999/10/10,001 м, составные и ломаные пути, обнуление на новой камере, ложная заявленная
длина, фактически экспортируемые sections, несколько коротких вводов из одной камеры,
оба профиля/три роли, all-variant preflight и выбор одного корректного варианта.
Evidence: ignored `.tooling/export85-preflight.8ikVYU/EVIDENCE.md`.

Пять старых economics tests использовали технический корень без камеры: новое правило
закономерно их отвергло. Fixture теперь содержит оплаченную камеру; денежные assertions
для самой трубы сохранены, включая 531991,79 ₽, исходные длины 2D, перенос координат и
отказ при расхождении на одну копейку. Это миграция некорректной fixture, не ослабление цены.

## Укорачивание не портит выходы из камеры

`FinalizedTerminalShortener` раньше принимал более короткий/дешёвый ввод с меньшим числом
поворотов, даже если он создавал почти параллельные выходы общей камеры. Теперь помимо
прежних обязательных проверок он сохраняет качество junction angles:

- число нерегулярных пар и суммарное отклонение не увеличиваются;
- минимальный угол сравнивается **для каждого узла**, чтобы улучшение общего счётчика
  не скрывало схлопывание одной пары;
- используется прежний допуск evaluator 0,5° для округлённой геометрии. Это не объявление
  всех углов камер обязательной нормой СП или изменение допуска препятствий.

Три синтетических regression cases падают на production `0913ea9`; остальные 16 контролей
того же класса проходят. На86 проходят все19. Бюджеты поиска, pricing и ранжирование ролей
не изменены. Логи: `.tooling/intake-20260925/source86-terminal-junction-final-red-reports/`
и `source86-shortener-final-red.log`.

Важно: историческое сравнение69→71→83 опровергло гипотезу, что shortener создал две известные
плохие пары на официальном наборе. Они уже были в69; сокращались другие вводы. Этот fix
предотвращает отдельную доказанную регрессию, но сам по себе не обещает исправить старые пары.
