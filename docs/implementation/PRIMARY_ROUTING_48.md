# Основной алгоритм: отбор готовых трасс и сравнение с экспертом

Дата: 2026-09-23. Версия: `global-tree-48`. Предыдущий локальный checkpoint:
[global-tree-47](PRIMARY_ROUTING_47.md). Изменения остаются локальными до отдельной команды на Git.

## Изменение поведения

1. Промежуточные деревья до и после локального удешевления сохраняются в портфеле. Удешевление
   может увеличить длину; короткая альтернатива больше не теряется только из-за этого шага.
   Сохраняются уже вычисленные деревья, повторного глобального поиска для них нет.
2. Дополнительные представители портфеля проходят `finish`: обязательные выходы из ОКС,
   включённую глубину, локальную регуляризацию, окончательный sizing, геометрическую проверку
   и экономику. Полный дорогой поиск инженерных перестроений для каждого из них не повторяется.
3. `FinishedRouteVariantSelector` назначает роли по фактическим итоговым значениям, а не по
   длине/стоимости черновика. `shortest` не ухудшает число нарушений углов и расстояний между
   коленами относительно своего проверенного исходного кандидата. `cheapest` сравнивает полную
   `calculated_cost`, включая камеры, врезки и штрафы. Полнота подключения приоритетна.
4. Допустимый `balanced` остаётся фиксированным инженерным контролем. Заменить его можно только
   при строго лучшем официальном score, не большей стоимости, длине не более 105% контроля
   и без ухудшения числа новых камер, нарушений углов/колен, поворотов и отклонений направлений
   в узлах. Коридор сравнивается с исходным контролем и не накапливается при нескольких заменах.
   Отклонения на тысячные доли градуса у полностью допустимых углов после миллиметрового
   округления не превращаются в новое нарушение: сохраняется штатный допуск evaluator 0,5°.
   Если несколько целей выбрали одну геометрию, она может занимать несколько ролей: не создаём
   искусственную «альтернативу» хуже найденной только ради трёх разных карт.
   Это ограниченная политика компромисса, не доказательство глобального оптимума.
5. При включённой глубине кандидат без завершённого безошибочного профиля каждого ребра
   исключается до сравнения полноты и целей. В 2D-режиме отсутствие профиля не блокирует расчёт.
   Регрессия воспроизведена тестом: более короткий путь через непроходимое вертикальное пересечение
   вытеснял допустимый обход. Теперь такой путь не выигрывает отбор.

## Эквивалентное ускорение

Обычные коридоры по-прежнему проверяются до дополнительных узлов вогнутых дворов. Если полный
упорядоченный список узлов pocket-графа побитно совпал с уже неудачным обычным графом при тех же
ограничениях и предпочтении, повторный поиск пропускается. Сравнение не округляет координаты,
учитывает порядок и все ordinates. Отличающийся граф обязательно исследуется.

Это ограниченное исключение повторной работы внутри одного вызова, не кеширование готовых
результатов между запусками. Старые поисковые бюджеты не уменьшены.

## Воспроизводимые картинки

`scripts/render-routing-comparison.mjs` строит две отдельные карты и сопоставление рядом из
фактических вершин результата и экспертного GeoJSON. Масштаб, охват и ориентация одинаковы;
маршруты не сглаживаются, точки ОКС не выдаются за камеры. Фон — текущий официальный набор;
несуществующий дорожный слой не дорисовывается.

```sh
pnpm compare:routing \
  --result .tooling/primary48-official.json \
  --reference-source /read-only/path/1.geojson \
  --out-dir .tooling/routing-comparison-48
```

SVG не требует новых зависимостей; PNG использует уже установленный `sharp` (при необходимости
`--sharp-module /path/to/sharp`). Без него доступен `--svg-only`. `--variant best` явно выбирает
`preferred_variant_id`; по умолчанию показан `balanced`. Версия/роль указаны на самой карте.
Metadata сохраняет хеши входов, метрики и источник. Для исходного `1.geojson` сверяются байты
и каждая извлечённая геометрия. Файл в Downloads только читается.
Путь `--result` обязателен: инструмент не подставляет старый результат по умолчанию.

Разметка Евгения — геометрический ориентир: 17 листьев, 11 узловых камер, одна существующая
корневая камера и два новых луча, 1 913,859 м. В исходнике нет подтверждённых ДУ и стоимости;
не выдавать её за прошедший инженерную приёмку проект.

## Проверка checkpoint

Java 11: 286 выполненных обычных тестов, три opt-in scale-теста пропущены; два теста
`OfficialDatasetRoutingTest` прошли отдельно. Полный случай 17 ОКС с глубиной — 492,612 с,
весь dataset-класс — 504,134 с. Реальный запуск через интерфейс/PostGIS без глубины — 554,817 с
(`cb5e43ad-3aa1-4950-af07-ba6c2f2606b5`). Прогоны частично шли одновременно; это наблюдения
локальной машины, не изолированный benchmark. Итоговый JSON live/unit совпал за исключением
отключённого `depth_profile`. Браузер отобразил результат и скачал настоящий GeoJSON.

Все три роли подключают 17/17 ОКС. `balanced` и `shortest` выбрали одну сеть:
1 899,051 м, 269 806 210,70 руб., score 13,251726900, 12 новых камер ветвления,
одно существующее место подключения / один новый луч; нарушений экспертных углов/spacing нет.
`cheapest`: 1 894,445 м, 264 775 893,97 руб., score 13,097060031, 11 камер,
но десять нарушений экспертного диапазона углов (опубликованы отдельным предупреждением).
Это не основание показывать дешёвую роль как инженерно чистую.

Кандидат `shortest` из `47` с 11 камерами имеет 13 настоящих поворотов против 12 у
контрольного `balanced`; он не проходит guard числа поворотов. Число внутренних вершин
полилиний 24/24 включает прямолинейные точки и не равно `EngineeringRouteEvaluator.bendCount`.
Правило не ослаблялось ради нужного количества камер.

Дополнительно прошли 31 web-тест, 21 тест скриптов, lint/typecheck/build и проверка разметки
специалиста. В API-логе после завершения были `ClientAbortException / Broken pipe` от закрытых
клиентских запросов; результат сохранён, повторное чтение и экспорт успешны. Это не ошибка worker.
Дальнейшая эквивалентная оптимизация подготовки препятствий — [global-tree-49](PRIMARY_ROUTING_49.md).
R4/R9, Compose, scale и restart-active-job этим документом не закрываются.

## Следующая работа по качеству

Исходные короткие деревья `6171362` и первого безопасного ускорения имели несколько врезок;
в `47` победило другое семейство — дерево от одного общего корня. Простое переименование
`SHORTEST` не меняет денежный критерий внутри `chooseAssignment`/`chooseTreeAttachment`.
Если сохранённых промежуточных деревьев недостаточно, следующий отдельный эксперимент —
ограниченный представитель с явной целью длины на всех трёх уровнях (direct, graft, whole tree),
с сохранением денежного контроля и замером дополнительной работы.

Общие коридоры также требуют развития: транзитивная группа с порогом соседства 500 м не обязана
иметь диаметр 500 м; фиксированные первые предложения не гарантируют разнообразие направлений
и типов корней. Развивать квартальные магистрали без жёсткой привязки к координатам/ID примера.
Не ослаблять официальный валидатор ради визуального сходства и не объявлять регрессию score
устранённой без нового измерения.
