# Доводка69: подготовка препятствий для повторных проверок геометрии

Дата:25.09.2026. Ветка `codex/routing-63-geometry`, `global-tree-69`.
Наследует [68](PRIMARY_ROUTING_68.md): исходные relocation-контроли не вытесняются repair.
Отдельная оптимизация с сохранением правил. Локальный API JAR61; master/VPS не менялись.

## Измеренная причина

30-секундный JFR-срез compiled67 во время shared-spine поиска содержал1615сэмплов основного
потока. В51,1% стека присутствовала `baseConstraints`, в58,3% — `validate`. Это включающие
друг друга доли **сэмплов**, не полного времени. Новые кандидаты заново строили те же
JTS-буферы препятствий/ДУ. Evidence `source67-group-spines.jfr` и execution samples — ignored;
JFR не коммитится. Ускорение полного расчёта этим не доказано.

## Изменение и границы

У конкретного `OfficialRouteValidator` появилась сессия одного расчёта. Окружение хранит
сессии по идентичности валидатора; используются именно его правила. Четыре geometry-вызова
planner используют эту сессию. Структурная проверка не менялась.

Повторно используется bounded `PreparedRoutingConstraints`: typed ID, фактический отступ и
точное сравнение исходной геометрии. Изменение геометрии/типа/ДУ, порядок/дубли объектов и
состав текущего окна не игнорируются. До512записей и100000резервируемых координат на сессию;
это не лимит байтов/всех временных объектов. Топология, actual geometry, собственный ввод,
нормаль, пересечения и результаты валидации вычисляются заново.

Публичный standalone `validate(nodes, edges, features)` и независимый exporter не используют
сессионную подготовку. Сессия не хранит готовые маршруты или ответы валидатора, однопоточна
и не переносится между runs. Существующий внутренний memoization подмаршрутов не изменён;
межзапускового кеша результатов не добавлено. Наследники валидатора вызываются через прежний
публичный override без подготовки: нельзя обходить более строгий hook ради ускорения.
