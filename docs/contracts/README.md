# Машиночитаемые контракты HeatRoute

В каталоге опубликованы три JSON Schema Draft 2020-12:

- `lct-2026-input.schema.json` — расширенный исторический профиль входа;
- `lct-2026-provided-dataset.schema.json` — базовый профиль совместимого входного GeoJSON;
- `lct-2026-output.schema.json` — строгий актуальный результат из `heat_network`,
  `heat_chamber`, `technical_node` и `variant_summary`.

JSON Schema проверяет форму каждого объекта, типы, допустимые ДУ и диапазоны координат. Инварианты
между объектами — глобальная уникальность ID, ссылки, направление к источнику, дерево, количество
summary и равенство итоговой стоимости сумме компонентов — дополнительно проверяются потоковыми
Java-валидаторами. Схема не заменяет эти проверки.

Неиспользуемые исторические типы `tie_in`, `heat_network_reconstruction` и
`heat_chamber_reconstruction` в актуальный output whitelist не входят.

CI компилирует все три схемы полноценным Draft 2020-12 валидатором, проверяет базовый входной файл
по его схеме и проверяет фактический результат экспортера по output-схеме. Поэтому файлы
нельзя менять как необязательную документацию: они являются тестируемой частью контракта.
