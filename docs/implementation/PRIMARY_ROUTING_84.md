# Основной алгоритм84 — направление подхода при переносе камеры

25.09.2026. Correctness checkpoint после [83](PRIMARY_ROUTING_83.md), **не релиз**.

## Исправление

`CorridorLinkApproaches` возвращает геометрию внешний узел → переносимая камера. Когда внешний
узел находится ниже по потоку, это обратное физическое направление. Ранее менялся только
порядок координат, а дорожный допуск и special-секции вычислялись как для прямого направления.

Теперь порядок хранения результата прежний, но `PreparedCorridor` получает `RouteTraversal`
по фактической upstream/downstream-инцидентности ребра. Допустимый проход не теряется из-за
угла входа с другой стороны дороги, а запрещённый прямой проход не выдаётся как кандидат.
Финальные проверки, отступы, льгота собственного корня, число альтернатив и поисковые бюджеты
не ослаблены. Общий алгоритм по-прежнему один; готовые маршруты между запусками не переиспользуются.

`ChamberZoneProbe.java` передаёт текущему `rebuildEngineeringZones` два динамически найденных

меняется только список seed, а не допуск. Действуют штатные ограничения: до4потребителей

Это не доказательство невозможности другой топологии. Лог `source84-zone-prototype.log`;
изменений production для этого опыта нет.

Следующий quality scope — определить, какие совместные геометрии/топологии отсутствуют
в ограниченном наборе подходов. Не увеличивать вслепую бюджеты и не ослаблять конечные проверки.
