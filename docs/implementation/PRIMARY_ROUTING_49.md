# Основной алгоритм: подготовка препятствий без изменения результата

Дата: 2026-09-23. Версия: `global-tree-49`. Предыдущие этапы:
[геометрия и общий алгоритм](PRIMARY_ROUTING_47.md), [отбор готовых вариантов](PRIMARY_ROUTING_48.md).
Это локальный checkpoint, не публикация в Git/VPS и не закрытие R-этапа.

## Причина и граница изменения

Профиль JFR реального API `48`: из 3 616 runnable execution samples рабочего потока
2 883 (79,73%) имели ближайшим проектным методом `OfficialRouteGeometryRules.baseConstraints`.
Большую часть выборок занимала повторная буферизация одних препятствий. Это частоты выборок
стеков, не точные доли wall time; inclusive-группы нельзя складывать.

`PreparedRoutingConstraints` готовит неизменные ограничения внутри **одного** окружения расчёта.
Новый запуск начинает подготовку и поиск заново; готовые маршруты между запусками не переиспользуются.
Логика генерации вариантов, бюджеты поиска, цели, размеры отступов и независимый финальный
валидатор не изменены относительно `48`.

- На каждом запросе по-прежнему читается его исходное пространственное окно. Ничего вне
  результата этого чтения в список ограничений не добавляется.
- Повторно используется только геометрическая подготовка с совпадающими ID, разрешённым типом,
  фактическим отступом и точной исходной геометрией. Сравниваются XY/Z/M, SRID, precision,
  типы геометрии, структура последовательности и factory; координаты не округляются.
- ДУ здания группируются по реальному отступу 5/7/9 м из существующего каталога, без второй
  копии табличных порогов. Проверка недопустимого ДУ сохраняется, в том числе при повторном обращении.
- Сохраняются все дубликаты и стабильный порядок. Исключения для своего здания и подходов к
  концам применяются заново после подготовки, поэтому послабление одного пути не протекает в другой.
- Владение геометрией явное: сохраняется копия без неиспользуемых metadata. Исходные feature и
  произвольные JSON-атрибуты не удерживаются. Потребители ограничений используют их только для чтения.
- LRU ограничен 512 записями и 100 000 координат исходников вместе с буферами. Крупный объект
  вычисляется обычным способом, но не удерживается. Лимит не удаляет препятствия из проверки.
  Это не байтовая гарантия памяти всего job; большие входы всё ещё требуют отдельного scale gate.

## Проверка

Java 11 обычный gate: 304 теста, 0 failures/errors, 3 явно пропущенных opt-in scale-теста
(301 выполнен). Новые 13 тестов подготовки покрывают все 18 официальных ДУ, изменения геометрии,
Z/M/SRID, дубликаты, владение, вытеснение/переполнение, invalid DU и 450 случаев endpoints/exemptions.
Два интеграционных теста окружения проверяют отдельные пространственные запросы, локальность
послаблений, повторное использование между эквивалентными ДУ и отсутствие переноса между запусками.

Полный официальный dataset-класс: **2/2 PASS**, 276,960 с. Случай 17 ОКС с глубиной —
**273,074 с** против 492,612 с в `48` (сокращение примерно на 44,6%). Все 86 профилей рёбер
трёх ролей завершены без ошибок. Всего выполнены **303 Java-теста**, три opt-in scale-теста
остаются пропущенными, а не пройденными.

Свежий живой job `bb452aab-2b23-4374-a09b-88b26d981ebc` запущен кнопкой «Новый расчёт»:
**286,960 с** от создания до сохранения результата против 554,817 с в `48` (примерно на 48,3%
меньше). API использовал PostgreSQL/PostGIS, неизменный официальный import
`7eebc444-9717-4ce5-8fcf-de19d00ce63d`, профиль stable без глубины. Прогоны dataset/live
частично шли одновременно на одной машине; это наблюдаемые локальные времена, не изолированный
benchmark и не обещание той же длительности на сервере жюри.

Проверка эквивалентности `assert.deepStrictEqual`:

  все координаты, узлы, рёбра, секции, ДУ, расходы, профили глубины, стоимость, роли, ранги и issues.

  включая 12/12/11 новых камер. Технические вершины экспорта не выдаются за тепловые камеры.

  Ускорение не получено сокращением перебираемых вариантов.

`balanced`: 17/17, 1 899,051 м, 269 806 210,70 руб., score 13,251726900, 12 новых камер,
одно существующее место подключения и один новый луч. Новых камер врезки нет.
Нарушений обязательной геометрии/sizing и экспертных bend/spacing нет.

## Воспроизводимость и эксплуатация

```sh
pnpm compare:routing \
  --result .tooling/primary49-official.json \
  --reference-source /read-only/path/1.geojson \
  --out-dir .tooling/routing-comparison-49
```

Карты используют фактическую геометрию и один метрический масштаб. По умолчанию показывается
`balanced`, не самый дешёвый кандидат с инженерными предупреждениями. В `comparison-metadata.json`
записываются входные SHA, версия, роль и реальные метрики. Экспертная разметка — ориентир,
не официальная проверка ДУ, стоимости или глубины.

Локальный API запускать из отдельной версионной копии JAR, а не из перезаписываемого Maven
`target/heatroute-backend.jar`. Пересборка файла под работающей JVM может сломать позднюю загрузку
классов и штатное завершение. Перед переключением worker проверить пустую активную очередь,
штатно остановить старый процесс, запустить новую копию и проверить readiness плюс свежий job.
Сохранённые старые runs и их происхождение не переписываются.

## Открытые границы

Основной вариант пока имеет 12 камер против 11 в разметке специалиста. Одна камера меньше ценой
дополнительного поворота — отдельный компромисс, а не автоматическое улучшение. Общие квартальные
магистрали и более короткие семьи деревьев остаются следующим направлением; см. `48`.
Официальный score основного варианта всё ещё хуже исходного `6171362`, хотя геометрия чище,
камер/врезок меньше и стоимость ниже. Глобальный оптимум не доказан.

Следующий quality gate: получить ещё одного представителя общих коридоров без привязки к
координатам/ID примера, удержать 17/17 и независимую валидность, сравнить число камер,
настоящих поворотов, длину, полную стоимость и score. Не продвигать кандидат только за
сходство с картинкой. Для скорости — повторно профилировать уже `49`; не переносить долю
старого hotspot на новый pipeline и не уменьшать поисковые бюджеты без контроля качества.

В этой macOS-среде нет Docker и pwsh. Native Java/PostGIS и web-команды не заменяют обязательные
`scripts/dev.ps1`/Compose, restart-active-job и scale gates. R4/R9 остаются открытыми.
