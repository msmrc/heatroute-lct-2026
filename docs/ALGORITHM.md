# Алгоритм обязательного 2D-расчёта

## Поток обработки

1. Java API потоково инспектирует один GeoJSON, одновременно считает SHA-256 и применяет strict
   либо явно названный compatibility-профиль.
2. Объекты сохраняются в PostgreSQL/PostGIS в WGS84 и EPSG:32637. Повтор contract+SHA возвращает
   существующий import.
3. Валидатор строит существующую топологию, проверяет ссылки или геометрическую связность и
   формирует допустимые врезки в камеры/участки.
4. Для всех ОКС одним запуском строятся independent, shared и diverse стратегии. Visibility search
   использует prepared geometry и adaptive STRtree; каждый кандидат после упрощения повторно
   проходит независимую проверку.
5. Принятые линии нормализуются в дерево/деревья. Разветвления и врезки становятся камерами,
   изменения инженерных параметров — technical nodes.
6. Расходы суммируются снизу вверх. Официальный каталог назначает минимальный ДУ, удовлетворяющий
   расходу и непрерывной предельной длине.
7. Добавленный расход распространяется по существующей сети к источнику. Если required DU больше
   baseline DU, формируются участки и камеры реконструкции.
8. Ограничения применяются и во время поиска, и финальным валидатором. Разрешённые пересечения
   размечаются `special`; конкретное разрешение не отменяет остальные правила.
9. Версионируемый каталог считает компоненты стоимости, penalty для неподключённых ОКС, длину,
   score и deterministic rank.
10. Adapter формирует семь официальных типов, независимый validator проверяет whitelist полей,
    типы, ссылки, уникальность IDs и WGS84, после чего Jackson пишет FeatureCollection потоково.

## Отказоустойчивость

Run и job неизменяемо сохраняются в PostgreSQL. Workers забирают задания через `SKIP LOCKED`,
имеют bounded concurrency и lease heartbeat. Отмена кооперативная; истёкший lease можно безопасно
перехватить после остановки процесса. Ошибка одного ОКС создаёт partial result с ID и причиной,
а не удаляет успешные маршруты остальных объектов.

## Границы применимости

- расчётные расстояния и площади выполняются в EPSG:32637, API/export — WGS84;
- обязательная модель остаётся самостоятельным 2D-результатом; optional R8 строит поверх каждого
  участка проверенный продольный профиль и явно сообщает конфликт, не подменяя им успешность 2D;
- supplied dataset compatibility не заменяет отсутствующие flow/upstream/diameter значения;
- exact 3 GiB input, ≥500 MiB output и 50 concurrent API sessions измерены отдельно от
  geometry-representative maximum-topology throughput;
- `railway` обрабатывается консервативно до официального уточнения.
