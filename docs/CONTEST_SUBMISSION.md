# HeatRoute — краткое описание конкурсного решения

## Задача

HeatRoute автоматически строит варианты подключения всех перспективных объектов к существующей
тепловой сети. На вход подаётся один GeoJSON, на выходе получается до трёх проверенных вариантов
с трассами, камерами, врезками, диаметрами, реконструкцией, стоимостью и рейтингом.

Ручная дорисовка маршрутов не требуется. Один запуск обрабатывает весь район и учитывает общие
стволы, отдельные подключения, пространственные запреты и специальные переходы.

## Что увидит эксперт

1. Загрузка исходного файла и понятный отчёт о качестве данных.
2. Автоматический расчёт всех ОКС с индикацией прогресса.
3. Три содержательно разные стратегии на интерактивной карте.
4. Для каждого участка — расход, ДУ, длина, способ прокладки, глубина и стоимость.
5. Для каждого варианта — подключённые ОКС, реконструкция, полная стоимость, score и rank.
6. Строгий GeoJSON, который можно независимо проверить опубликованной JSON Schema.

## Почему результату можно доверять

- Все расстояния и пересечения считаются в EPSG:32637, API принимает и возвращает WGS 84.
- Маршрут строится с учётом препятствий, затем проверяется отдельным валидатором.
- Расходы суммируются снизу вверх; ДУ выбирается по официальной таблице из 18 значений.
- Предельная длина контролируется непрерывно и сбрасывается только при смене ДУ.
- Добавленный расход распространяется по существующей сети до источника.
- Стоимость считается по нормативным ставкам; итог проверяется суммой компонентов.
- Ошибка одного ОКС не уничтожает расчёт района: сохраняется частичный результат и точная причина.
- В каждом запуске сохраняются SHA-256 входа, версии контракта, алгоритма и параметры глубины.

## Инженерное преимущество

Помимо обязательной двухмерной постановки реализован продольный профиль. Для каждого нового
участка алгоритм выбирает глубину, проверяет уклон и вертикальные пересечения, а при невозможности
прохода меняет XY-трассу и повторяет расчёт. В выгрузке присутствуют технические узлы и точные XYZ
координаты оси парной прокладки.

## Измеренная готовность

| Проверка | Результат |
|---|---|
| Официальный файл | 144 объекта, 17 точек спроса, 204 кандидата врезки |
| Полный расчёт | 17/17 ОКС, три валидных варианта |
| Увеличенная топология | 288 объектов, 34 ОКС, 408 кандидатов, 34/34 подключены |
| Java 11 / Ubuntu 22 | 2:14.65 на финальном SHA, пик RSS 406 608 КиБ |
| Большой вход | ровно 3 ГиБ при heap 512 МиБ |
| Большой выход | не менее 500 МиБ при heap 512 МиБ |
| Параллельный API | 50 одновременных запросов, без дублей импорта |
| Чистое развёртывание | Ubuntu 22, docker-compose 1.29.2, restart recovery |

## Честная работа с исходными данными

Переданный организатором файл не содержит базового расхода и направления существующих участков,
а также диаметров камер. HeatRoute не подставляет правдоподобные числа: интерфейс показывает
конкретные предупреждения, а официальный score и строгую выгрузку разрешает только при полном
контракте. Полный pipeline подтверждён отдельными contract-complete тестами.

## Технологии

Java 11, Spring Boot 2.6.3, PostgreSQL 17/PostGIS 3.5, Liquibase, JTS, Proj4J,
React/TypeScript и MapLibre GL JS. Решение разработано командой Dragons.

Сценарий живого показа находится в `CONTEST_DEMO.md`, проверяемые критерии — в `ACCEPTANCE.md`,
машиночитаемые контракты — в `contracts/`.
