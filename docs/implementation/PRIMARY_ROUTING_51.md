# Обязательные повороты и ДУ новой камеры — source 51

Дата: 23.09.2026. Тип изменения: исправление поведения по §2.1 и §3.2 актуального
организаторского приложения, не рефакторинг и не подтверждение полного соответствия СП.
Предыдущая база: [PRIMARY_ROUTING_50.md](PRIMARY_ROUTING_50.md).
Проверенный live API остаётся на 49. Не подменять старые run новой версией и не переписывать
JAR под работающей JVM. Git/VPS в этом шаге не обновлялись.

## Изменения

- Новая камера врезки получает ДУ **max(все новые участки, примыкающая существующая сеть)**.
  `ExistingNetworkSupportIndex` разрешает опору и общий конец участков через пространственный
  индекс; соседняя неприкасающаяся труба не участвует. Неизвестный/неверный ДУ, неподтверждённая
  опора, перекрытие или неоднозначное пересечение не заменяются ДУ50.
- `existing_incident_diameter` передаётся типизированно до оценки draft; при переносе корня
  разрешается заново. Поле входит в точное состояние refinement, даже в одном ценовом диапазоне.
  `OfficialChamberSizing` общий для расчёта и экспорта. Старые существующие камеры не строятся заново.
- Во всех ролях проверяются изменения направления **≤90°**, в том числе через узлы степени два.
  Миллиметровая погрешность зависит от длин отрезков, с верхним пределом 0,1°, а не общим
  разрешением поворота 90,1°. Углы разных ветвей камеры не объявлены обязательными 90°.
- Обнаружена регрессия прежнего подхода: диагональ к короткому перпендикулярному лучу давала
  поворот >90°. Добавлен локальный кандидат с двумя прямыми углами, повторной проверкой всего
  пути и новой разметкой тарифных участков. Он не разрешает пересекать препятствия/другие трассы.
  Тест потребителя без собственной врезки снова подключает **2/2**, сохраняя обязательную геометрию.
- Экспорт повторно разрешает ДУ опоры из импорта и проверяет камеры, платные лучи, сохранённую
  арифметику и повороты потоковым обходом координат. Проверяется сумма стоимости физических
  экспортируемых объектов + платных лучей. Старый неверный результат требует перерасчёта,
  а не молчаливого изменения сметы. Это дополнительная защита, не заявление о полном независимом
  повторе всех геометрических и гидравлических предикатов при экспорте.
- Ревью дополнительно выявило различие источников геометрии: валидатор читал `edge.coordinates`,
  writer — секции. `SavedRouteGeometry` проверяет фактически экспортируемую цепочку секций,
  включая стыки и концы, и сопоставляет её с ребром двумя монотонными курсорами. Дополнительные
  точки разбиения разрешены с погрешностью 2 мм; обратный ход, другой путь, разрывы и координаты
  точнее внутреннего миллиметрового формата отвергаются до первой feature. Память обхода O(1).

## Осталось до цели

Во время нового all-17 снят **120-секундный фрагмент JFR**, а не профиль всего прогона:
`.tooling/primary51-search-profile.jfr`, сводка `.tooling/primary51-profile-summary.json`.
3281 execution sample главного потока; ближайший прикладной frame — `intersectsInterior`
в 67,5% выборок, sparse-state distance lookup в 7,5%, navigation nodes в 6,6%, base constraints
в 6,1%. Это доли выборок этого окна, не точные проценты общей длительности. Прогон с JFR
не является изолированным сравнительным benchmark. Громоздкая промежуточная JSON-выгрузка
профиля удалена; исходный JFR и компактная текстовая выгрузка сохранены.

Следующий адресный срез: обязательный предел поворота внутри направленного поиска до дорогой
проверки видимости. Сейчас он учитывается штрафом/последующим допуском. Проверить равенство
с исчерпывающим малым графом и сохранение достижимости; не обещать выигрыш без нового all-17.

Далее продолжить общие фасадные стволы, подходы сохраняемых узлов,
удаление трёх лишних камер и сокращение бесполезной
финализации. Более строгий валидатор сам по себе не улучшает поиск и не доказывает ускорение.
Ни один R-этап и цель «как у Евгения» этим промежуточным gate не закрыты.
